    Client,
    ClientSerializer,
    ClientDeserializer

Запуск реализуется с помощью docker-compose up -d
Моя последовательность действий заключалась так:

```
#1 Поднял кафка кластер с помощью docker-compose up -d на kraft
#2 Посмотрел статус и имя контейнеров docker ps -a
#3 Вошел в shell среду случайного контейнера docker exec -it dee1f9c27da3 /bin/sh
#4 Создал топик с заданными параметрами
#  Хотел бы добавить, для возможности падения 1 брокера config={"min.insync.replicas": "2"},   # Минимум 2 реплики должны подтвердить запись, но не сделал, как понял - дефолт значение 1
#5 Добавил сервис app и опять выполнил docker-compose up -d
```


Добавил файл логов в volume и данные/ошибки пишутся в него. То есть работоспособность приложения можно проверить таким образом.

Приложение работает с Кастомным сериализатором ClientSerializer и десериализатором ClientDeserializer. 

Создал класс Client, от него сделал экземпляр с тестовыми
данными (аттрибуты clientId и name), сериализовал их и отправка происходит с помощью Producer.py

Данные идут в топики по партициям и на них натравлены две группы консюмеров (по заданию)
Первая консюмер группа - SingleGroup
Вторая консюмер группа - BatchGroup

Они забирают данные из топика по партициям (разные группы могут параллельно читать партиции, но в рамках одинаковой группы у них общие оффсеты)
Десериализуют их и пишут в логи. Ошибки также ловятся и пишутся в логи



Проверить работоспособность приложения можно, выполнив docker-compose up -d схожим образом, как сделал я
